# Architecture

The current campaign is the ten-level Earth chapter described in [Earth puzzle design](earth-level-design.md); all ten canonical editor JSON documents are the runtime source. The original multi-element traversal and timed prototype below remain available separately.

## Responsibility boundaries

React owns the Veylith menu, level selection, initialization/error status, orientation reminder, gesture/button controls, run HUD, pause/completion panels and optional character lab. `GameCanvas` creates one per-mount `ActionState`, imports the engine asynchronously, and retains the cancellation and duplicate-instance protections under StrictMode. It observes only initialization readiness; React receives discrete world state and a stopwatch snapshot at most every 100 ms.

Phaser owns rendering, animation, physics, levels and gameplay. Zustand holds application status/preferences and persistent campaign results. No physics, movement or frame-by-frame world state is stored in Zustand.

## Startup and lifecycle

1. `main.tsx` mounts React in StrictMode and applies the shared background.
2. `GameCanvas` requests `createGame`, passing its action state. Only development URLs with `?preview=characters` dynamically import the existing lab scene and bridge.
3. `createGame` guards duplicate containers, observes resize and native/web app activity, and creates BootScene plus the requested scene.
4. `BootScene` loads the scoped character manifest. Gameplay requires all four idle sheets; missing optional traversal animations are reported and excluded from registration, so Player can use idle. The inspection lab retains strict validation of every requested sheet.
5. `MainScene` creates Ancient Forest by default, the prior puzzle at `?level=puzzle`, or the development test stage, a `PlayablePlayer`, static colliders and the keyboard adapter. Readiness enables touch controls. The lab instead creates the original visual Player and controls.
6. Each scene update consumes one action snapshot, handles restart, computes motor decisions and applies velocities to Arcade Physics. The puzzle reads resolved foot contact and element to update the plate, gate and exit. Arcade owns integration and collision separation. The visual sprite follows the resolved body's foot position.
7. Inactivity, window blur and disposal clear held actions and pending presses. Game pause disconnects the keyboard adapter; resume reconnects it so missing native keyup events cannot leave its alias tracking latched. Unmount cancels pending imports, removes UI, disconnects listeners, detaches the canvas and requests actual Phaser destruction. Scene shutdown disposes keyboard input, collider and player. The existing sleeping-loop wake and core-plugin retention allow fresh mounts.

## Player and physics

`Player` remains the visual entity shared with the lab. It owns element, facing, animation, supplied metadata alignment and cleanup; its new `setPosition(x, feetY)` follows the gameplay body. `PlayerAnimationController` and the 29-animation registry are retained.

`PlayablePlayer` pairs that sprite with an invisible **55.8 × 156.6** Arcade rectangle. Body geometry does not depend on texture/frame dimensions, animation pivots, mirroring or element. The visual reference height is 180 (10% smaller, like the collider), using the same 455-pixel source reference and mirrored origin correction. Source PNGs and measured foot metadata are unchanged.

`PlayerMotor` makes device-independent movement decisions. It owns the current element and the Fire extra-jump budget. Grounding requires a downward contact and nonnegative velocity, preventing stale contact flags between fixed steps from refilling a jump immediately after launch. Holding jump generates only one press; transformation never resets the air-jump budget. Landing refills it. Earth uses a 620 jump impulse and 900 ascent gravity (about 208 px in Arcade), clearing the standard 180 px heavy block with one jump. Water retains its 560 impulse; Earth retains 2000 descent gravity and its own horizontal speed. The campaign channel and route audit account for this raised Earth jump. Fall speed and gravity change with the element without teleporting the body or restarting the jump.

`levels/testLevel.ts` supplies a solid floor and four static ledges. `playerCollision` assigns all four player contact flags for every pair from the solid's resolved `player-collision` metadata. Optional schema-v1 `collider.playerCollision` stores `top`, `bottom`, `left` and `right` booleans; contact directions are opposite the touched face. Without overrides, terrain/platforms/decorations/Box Colliders support feet and allow side/underside passage; blocks, mirrors, doors, breakable walls and barriers also retain sides. Explicit overrides are shown by the shared inspector and validated before saving. Defaults never rewrite existing JSON or saves. World bounds, block/block and projectile rules are independent. Conveyor carry applies the configured left/right face; top-support reconciliation and platform rider checks honor the top face. `playerCollision.test.ts` uses the installed Arcade integrator/separator, `colliderFaces.test.ts` checks validation/history/serialization, and `collider-faces-editor-smoke.js` saves and plays real editor choices. `jump-through-smoke.js` covers default passage, gates, belts and restart. All ledges can be reached sequentially as Water; Earth can reach the lowest ledge. The test stage is selected using `?level=test` in development. Ancient Forest is now the default; the prior puzzle is described below. Water/Fire projectiles, Air impulse and Earth smash/plunge are implemented. Damage, enemies and spatial checkpoints are not implemented. Campaign progression is implemented separately from the world.

## Ancient Forest

The default forest level keeps resource metadata, layout, rendering and discrete traversal state in separate modules. `BootScene` queues its 24 environment images only when selected and validates required textures before scene startup. `AncientForest` assembles 128-pixel tiles with separate rectangular collision strips; it uses measured transparency bounds for props and strip edges without changing artwork.

The world spans 5,888 × 1,100 pixels; the camera follows horizontally within a 1,280 × 720 logical viewport with the existing capped Retina policy. Three viewport-sized repeating backgrounds provide parallax. Water platforms, a 280-pixel Fire ledge and an elevated Air launch lead to inactive ruins and a grounded portal exit. A fall restarts the scene. Completion freezes the engine, commits the run result once and opens the React completion panel.

`ForestState` produces discrete hints/completion through the existing `LevelProgress` bridge. `ForestHud` renders them without per-frame React state. The previous puzzle is the second campaign level; `?level=puzzle` respects the saved unlock state; the sandbox and character lab remain development-only. See [Ancient Forest](ancient-forest.md) for exact assets, geometry, testing and limitations.

## First puzzle

`levels/firstPuzzle/layout.ts` defines the split floor, elevated plate, full-height gate and exit. `FirstPuzzleState` owns activation, the six-second timer and completion. Only grounded Earth at the plate's foot height can refresh the timer; air contact, standing below it and other forms cannot. Leaving the plate or transforming starts the countdown. A player who has crossed the gate can finish even if the timer expires before landing at the exit.

`FirstPuzzle` owns the scene geometry and maps the state to collision enablement and visual feedback. The door stays non-solid while overlapping the player at expiry, then closes once clear, preventing entrapment. Falling to the lower world boundary restarts the scene, clearing timer, element and input. Completion suppresses movement until an explicit restart. Scene-owned objects are removed by Phaser shutdown; colliders, input listeners and puzzle UI progress are released by MainScene cleanup.

A per-canvas `LevelProgress` bridge publishes only changes to phase, displayed seconds and activation. `PuzzleHud` uses `useSyncExternalStore`; position, physics and the running timer remain outside React/Zustand. No per-frame React physics updates occur. Restart from R or the UI emits the typed `restart_level` action and consumes it once through `ActionState`.

## Input boundary

Both DOM pointer controls and `gameplayKeyboard` emit the existing `GameInputAction` union. Keyboard implements `InputSource`; touch controls dispatch these actions with a source per pointer. They never modify velocities or the Player.

`ActionState` aggregates held actions by source, retains quick jump and power taps until one update consumes them, and consumes element requests once. MainScene rejects all manual element requests. Gameplay has no selector buttons or number-key adapter; only gem pickups transform the player. The separate development lab retains visual inspection controls. Opposite directions cancel. Releasing one pointer does not release another pointer or a keyboard hold. A second press is needed for Fire's extra jump. Air can glide by holding jump or `use_ability` while descending.

Keyboard aliases are aggregated before emitting actions. Repeat events, browser shortcuts and typing are ignored. Touch buttons use pointer capture, release on pointerup/pointercancel/lostpointercapture, and support Space/Enter activation. Blur, visibility loss, native inactivity and teardown clear input. Gameplay is available in both development and production; lab controls remain excluded from production.

## Assets and fallbacks

Paths, frames and foot metadata remain centralized in `assets/characterSheets.ts`. Gameplay loads 24 character sheets: idle/run/jump/fall for all elements, Fire double_jump, Air glide_loop, Water/Fire attack, Earth smash and Earth push_start/push_loop/push_end. Nine unique effects use a separate audited manifest. Total texture pixels require approximately **173.375 MiB decoded RGBA**, excluding renderer buffers, browser image copies and other overhead. Ancient Forest additionally loads 32 images / 37.546875 MiB; its combined source texture budget including the new gem/transformation scope is approximately 306.422 MiB including the animated forest props. The original lab loads 29 sheets / 170 MiB and does not load environment textures. The 12 gem sheets add 20 MiB and the four transformation strips add 32 MiB. They are gameplay-only and all optional; failed or malformed art uses visible runtime fallbacks. All supplied public assets remain in the offline build, but only the scoped sheets are requested/uploaded at runtime.

Land and glide-start artwork are retained for inspection but not loaded for the MVP. Gameplay transitions directly to idle/run and glide_loop. Unsupported or failed optional sequences use idle without blocking physics; missing essential idle art reports the filename. Earth pushing plays its original entry, loop and release sequences while grounded beside an unsolved supported block. `PushAnimationState` changes presentation only; jump, fall and power remain higher priority. Contact detection shares the physical block-pushing rule in both directions. Power poses fall back to idle; effects fall back to colored shapes if unavailable.

This is a bounded initial loading strategy, not an iPhone memory/performance certification. See [gameplay MVP](gameplay-mvp.md) for measurements and remaining limits, and [asset audit](asset-audit.md) for the original delivery.

## Powers and effects

`PlayerPowers` owns per-form cooldowns, one airborne Air impulse, and Earth plunge/impact decisions. `PlayablePlayer` applies these after ordinary movement, preserving collision geometry and transformation. `PowerEffects` sweeps short-lived projectiles against enabled static bodies, renders the nine unique effect clips and displays a recharge bar. Its objects are bounded and explicitly destroyed on scene cleanup; lifetimes advance only with game time. Read [elemental powers](elemental-powers.md) for controls, resource limits and validation.

## Audio

`services/audio/catalog.ts` registers the 74 real WAV paths. `AudioEngine` owns one gesture-unlocked Web Audio context, deduplicated fetch/decode, a 12 MiB decoded-buffer cache and bounded voices (28 total, three per cue). Phaser's independent audio manager is disabled. `AudioRuntime` synchronizes saved mute/volume and web/native activity; it cleans up listeners under StrictMode. No third-party audio dependency or native plugin is required.

`createGame` owns a cancellable world `AudioScope` and a separate result scope. Pausing/completing the game silences its world while UI can still play. Scene restart cancels pending one-shots and loops; game teardown disposes both scopes. Background/mute cancels delayed result sounds, preventing stale rewards on return. `bindRunAudio` listens to confirmed completion transitions rather than React renders and never changes progress.

`MovementAudio` observes accepted motor decisions and actual grounded displacement. `PowerEffects`, `GemSystem` and puzzle adapters emit contact/collection/state transitions. `WorldAudio` observes committed simulation state and actual elevator/bridge movement; `SceneSound` attenuates object sounds by player distance. Decorative props use their existing visual state names, without changing colliders or adding interactions. The editor canvas and character lab remain silent; playtest has isolated world/results scopes. See [audio integration](audio-integration.md) for event mapping, limits and validation.

## Display and scaling

`config/settings.ts` retains the 1280 × 720 virtual world and DPR cap of 2. Phaser 3.90 does not support a renderer resolution option: `WorldCamera` multiplies the backing-canvas render scale by the level's optional `cameraZoom` (0.25–1.5, default 1). Canonical campaign levels and editor playtests use the same saved lens zoom; legacy levels and prototypes retain their original view. Physics dimensions are independent of this zoom. `Scale.FIT` preserves aspect ratio, while CSS owns dynamic viewport sizing and safe-area insets. The overlay controls use the same safe-area insets, prevent scroll/selection and keep touch targets at least 44 pixels tall.

`ForestPuzzle` scales its camera-follow framing offsets by the inverse lens zoom. `ForestBackdrop` scales fixed 1280 × 720 repeating surfaces to cover the visible viewport, compensating for Phaser's zoom origin and parallax. Zooming out does not allocate larger background canvases. Schema validation rejects nonfinite or out-of-range camera values before saving/playtest; the optional field preserves version-1 document compatibility.

Rotation refits the canvas without recreating gameplay. Portrait browsers show the existing landscape reminder. Native landscape orientation remains configured in Info.plist. Moving between screens with different DPR requires a reload to resample backing density.

## Validation

Tests cover the existing assets/animation/lifecycle invariants plus motor rules, transformation budgets, alias aggregation, independent touch holds, cancellation, input reset and asset fallbacks. Browser checks exercise real Arcade collisions, traversal, native multi-pointer events, resizing and actual mount/destruction. Native compilation, iOS WebView behavior and physical-device memory/performance require Xcode and an iPhone.

## Gem transformations

Level data owns `initialElement` and `gems: { id, element, x, y }[]`. MainScene creates a fresh `GemSystem` and `PlayablePlayer` on every restart, including automatic fall retry. `GemState` defaults to a 44 × 80 overlap area in the legacy levels; canonical level documents supply their own independent pickup collider. It consumes each ID before applying transformations. Art does not alter collision geometry. Spawn and Collect are one-shots, Idle loops; a game-time lifetime ends missing or stalled animations too. Completion disables new pickups.

`PlayablePlayer.transform` changes the motor and sprite immediately without touching the body, position, facing, velocity or airborne resource budgets. Normal movement/gravity resumes on subsequent frames; the transform itself applies no impulse. The destination effect follows the current player for 0.5 seconds, with at most one active transformation visual. `GemSystem.destroy` clears remaining gem visuals and VFX on shutdown. No React or Zustand state is used per frame. See [gem system](gems.md) for asset measurements and fallback rules.

`ForestAnimatedProps` composes the optional water/portal loops with static frames and runs the door opening/closing cycle. `forestAnimations.ts` loads three measured grid sheets and the empty portal frame only for Ancient Forest (43.5 MiB). The door closing PNGs are exact reversed duplicates of the opening cells, so the cycle reuses one texture. Optional sheet validation supports explicit column counts while preserving horizontal-strip defaults. Static fallbacks keep the route playable if these resources fail; no puzzle state or collision is added.

## Veylith application flow and persistence

`App` owns navigation and one stable run bundle (`ActionState`, `LevelProgress`, `RunSession`). The menu does not create Phaser. Starting an unlocked level mounts `GameCanvas`; pause/resume and restart reuse the game; leaving the run destroys it. Existing StrictMode cancellation, duplicate-container protection, immediate canvas removal and deferred engine teardown remain intact.

`RunSession` owns attempt metadata outside React/Zustand. A monotonic clock samples active intervals and emits at 100 ms display boundaries or discrete changes. MainScene starts a fresh clock on every scene create (including fall retry), reports gem-driven element changes and completes the run only after the real level completion rule. Completion is latched once. Scene/game suspension freezes physics, animation, effects and input together; inactive/manual/completed states cannot be resumed by native foreground notifications alone.

`services/progress/progress.ts` contains pure rating, unlock, best-record and differential-reward rules plus validated storage codecs. `progressStore` loads once, commits discrete level choices/results synchronously and reports save failures. The first schema is version 1; unknown future versions remain untouched and play in memory. Invalid data is copied to a recovery key before replacement. There is no earlier persistent schema in this project to migrate.

`components/ui/assets.ts` lists actual supplied PNG paths. React image/button wrappers keep semantic labels and CSS fallback surfaces. Movement retains pointer capture and typed action dispatch, and UI input still never writes player velocity. `RunHud` observes the world bridge for the original door countdown and new discrete forest-puzzle objectives. All application overlays respect safe-area insets and 44 px minimum action targets. See [Veylith UI](veylith-ui.md) for validation and limits.

## Ancient Forest puzzle campaign

`src/game/levels/data/forest-*.json` defines the ten canonical campaign levels; `forestPuzzles/layouts.ts` parses them and `schema/compile.ts` adapts them to runtime rules; `ForestPuzzleState` owns attempt-local objectives, latched target/gate state, physical plate contact and crossing/exit rules. `ForestPuzzle` adapts these rules to real Arcade bodies, supplied object-state textures and the shared `schema/renderObject.ts` renderer (the legacy levels retain `ForestTerrain`). `PowerEffects` accepts an optional `PowerInteractions` port: swept contacts select the nearest solid or target; the timed Earth strike reports the contacted breakable. The original levels have no interaction port and retain their behavior.

The ten entries are independently selectable. `campaignOrder.ts` provides pedagogical order without renumbering save IDs. `nextCampaignLevel` keeps them separate from the legacy two-level route; `isUnlocked` preserves the old wind-puzzle prerequisite. The existing v1 ledger remains valid. Read [campaign design and test instructions](level-design.md).

## Development visual editor

`main.tsx` dynamically imports `editor/EditorApp` only behind `import.meta.env.DEV` and `/editor`. Production tree shaking removes the editor, its styles and API client. `server/editorPlugin.ts` is a serve-only Vite middleware and has no preview/build or native endpoint.

`schema/types.ts` and `validate.ts` define the versioned JSON contract. Every editable object has stable identity, independent visual dimensions and box collider offsets. Both `EditorScene` and `ForestPuzzle` use `renderObject.ts`; the game creates actual Arcade bodies from the same document. `compileLevel` derives only the pure puzzle rules. Campaign time thresholds come from the JSON; reward and unlock policy remain in `catalog.ts` and the existing progress service. The original two prototypes remain separate and unchanged.

`EditorModel` publishes immutable document snapshots, selection, dirty status and bounded undo/redo. Phaser previews pointer motion locally; one committed action is published on release. Inspector edits commit at field blur. Level-height edits move the fall limit with the bottom edge, preserving its margin in the same undo transaction; existing objects remain in place. The editor draws the actual fall boundary and death zone independently of the grid. A separate explicit control aligns an old/custom fall limit with the bottom. Camera pan/zoom never mutate object coordinates. `EditorCanvas` defers construction to survive StrictMode cancellation, observes resize and removes scene/listeners/canvas on teardown.

Editor camera geometry shares a 1–300% zoom range across wheel, toolbar buttons and the percentage field. Fit centers the full level within the current viewport with a margin. Distant zooms coarsen only the visible grid in power-of-two steps, keeping line count bounded and snapping unchanged. Background texture surfaces stay 1280 × 720 and scale for display; zoom does not allocate a world-sized canvas. Navigation is development-only and leaves the document unchanged. The explicit **Aplicar zoom al juego** button copies an eligible canvas zoom into `cameraZoom` as one undoable edit; **Zoom al jugar (%)** edits the same field directly. Playtest uses the draft clone, and explicit save persists the field in canonical JSON.

Playtest clones the draft, mounts the existing `GameCanvas` with a document override and fresh `ActionState`, `LevelProgress` and `RunSession`. It does not register a campaign completion callback, so no coins or saved records change. Stop destroys gameplay and restores the same editor model/history. No preview element selector is used.

The local repository validates input, confines names to regular JSON files in the canonical level directory, rejects symlinks, checks ETag conflicts and serializes atomic writes. Middleware restricts access to loopback and same-origin requests with a per-process token and payload limit. Explicit saves invalidate loaded JSON modules for a later game reload without HMR reloading a dirty editor. Read [the editor guide](level-editor.md) for supported mechanism constraints and extension instructions.

`ForestPuzzle` owns a collection of `HeavyBlock` instances. Each owns a gravity-driven Arcade rectangle, terrain/plate collision and artwork following. Each pair of blocks is registered once for collision; every block participates in shared solids, transport and occupancy. Its body is non-pushable by ordinary collision separation; grounded Earth side contact supplies horizontal velocity. Airborne blocks retain that velocity, and plate activation requires supported contact at the actual plate height, with sufficient horizontal overlap. The latch freezes only the contacting block in place rather than teleporting through obstacles or freezing another block with the same destination. `ForestPuzzleLayout.blocks` compiles every block; `ForestPuzzleState` tracks docked block IDs separately from plate signals. A v1 `plateId: ""` is a free block with no latch or objective, usable as a movable step. Body dimensions/offsets come from the canonical collider, independent of image size. Any block lost below the fall limit requests the same full restart as a player fall. All block updates and cleanup run per instance. Before consuming player input, `settlePlayerSupport` reconciles at most 1 px of top-contact separation on a supported block. It ignores ascending players, unsupported blocks and side contacts so jumping from an unlatched block stays reliable without creating midair support. `heavy-block-smoke.js` verifies elevated drops, leftward pushes, ledges, sizes, occlusion, non-Earth contact, restart and editor playtest.

## Collectible coins

The canonical `coin` object has independent visual/collider bounds and an integer value from 1–1000. `coinAsset.ts` measures and loads the existing 256 × 256 RGBA `assets/ui/rewards/golden_elemental_coin.png` (alpha bounds 32,32–224,224; 0.25 MiB decoded). The editor and forest loader reuse this static image; no new files or animation sheets are created.

`CoinState` tracks attempt-local overlap consumption. `ForestPuzzle` hides collected views and exposes discrete value/total snapshots through `LevelProgress`; restart recreates all pickups. Coins never change elements or objective/exit requirements. `MainScene` passes only collected IDs through `RunSession.complete` on victory. The reward service resolves values from the canonical campaign document, ignores unknown/disabled/duplicate claims and adds only previously unbanked IDs. Optional per-level `collectedCoins` entries extend the v1 ledger; the balance must equal star entitlements plus all banked pickup values. Existing v1 records without the field remain valid. Playtest has no completion payout callback.

## Language and options

`preferencesStore` stores only UI language and mobile control mode, independently from `appStore` audio preferences and the campaign ledger. English is the default; both choices survive reload when storage is available. `services/i18n` provides typed UI copy and exact-source translations for canonical level text. Custom/edited strings without a translation retain their source. Neither canonical JSON nor save IDs are rewritten. Canvas text subscribes to locale changes and unsubscribes on its own destruction, so changing language never recreates the physics world.

`App` owns the options overlay and remembers whether it paused an active run. A run already paused stays paused when options close. Background content is inert; the dialog traps keyboard focus, supports Escape and restores focus. `OptionsMenu` uses the existing audio setters and `AudioRuntime` without a second engine or audio storage path.

On touch-capable devices, `GameplayControls` defaults to two screen halves. `TouchGestures` recognizes gestures in CSS pixels and dispatches only `GameInputAction`. The left finger holds movement beyond an 18 px horizontal dead zone; release stops it. The right finger emits one jump after a 28 px upward swipe and retains jump for Air glide until release. A right tap within 12 px and 350 ms emits one power on release. A swipe never emits a tap power. One pointer per half is captured independently, and cancel/lost capture, resize, blur, hidden document and unmount release gesture holds. An optional saved Buttons mode and unchanged keyboard aliases remain available. Options control neither physics nor elemental selection.

### Optional puzzle clues

Canonical Earth documents have optional `puzzle.brief` and `puzzle.hints` fields within schema v1. Validation constrains the brief and two or three nonempty clues. The editor edits the same fields; `ForestPuzzleState` publishes them as immutable UI content. `PuzzleHints` owns only disclosure state, never game signals or rewards. Existing documents without this field retain their previous hint behavior. `earthValidation.ts` is an additional campaign design audit used by tests; it is not an exhaustive solver or a replacement for browser playtests.

### Reflector hold interaction

`ReflectorInteraction` resolves grounded proximity, line of sight and the nearest enabled reflector using live bodies. `MainScene` routes `abilityHeld` and typed aim/turn actions into attempt-local `WorldState.mirrorAngle`; while holding it masks player movement, jump and powers. Release cancels aiming before consuming angle changes. Escape requires a fresh hold. Scene pause/teardown already resets every input source. UI teardown does not enqueue a delayed close that could cancel the next hold.

`WorldControls` observes a throttled `ReflectorSnapshot` (at most 12.5 Hz for angle display). `ReflectorControls` only adapts pointers/keys; physics and optics remain outside React. The held touch button stays mounted at its original position. `AdvancedOptics` computes arbitrary-angle reflections and reuses a bounded pool of tile sprites. `advancedArt` rotates the existing head about its measured pivot independently of the collider. Optional v1 fields `angle` and `rotatable` retain backward compatibility and editor/playtest isolation.

### Grounded Earth selection map

`MenuScreens.LevelSelect` keeps ground coordinates for the ten Earth IDs in a shared proportional scene with the original background. `level-map.css` owns marker flattening and scale, without shadows. ### Veylith environment expansion

`environmentManifest.json` is a build-time inventory of 155 inspected original PNGs and 12 platform families. `environmentCatalog.ts` provides a finite `environment:<name>` asset union, explicit own-property validation, dependencies and platform collider presets. The generator reads the 19 supplied manifests, checks PNG dimensions/alpha and records source hashes in `asset-environment-expansion-audit.json`; its filesystem operations never enter the application bundle.

Existing schema-v1 `decoration` and `platform` objects hold the new resources. Only registered family centers are valid modular platform assets; arbitrary paths and using new art for mechanisms are rejected. `renderEnvironment.ts`, called by the shared renderer, preserves full transparent canvases and assembles left/center/right modules within the visual bounds. Colliders remain separate, with an explicit undoable fitting action in the editor. Source repeat axes determine horizontal/vertical extension and two-axis tiling. Unique sprites scale uniformly. Platform caps keep their shape and only the final repeated cell is cropped. The shared renderer reuses the original textures with bounded Image instances, avoiding area-sized TileSprite backing canvases. Validation counts expansion cells at their chosen scale toward the existing 8192-piece level budget and caps each expansion object at 4096 cells; invalid drafts also render only that bounded preview. `editor/environmentResize.ts` applies the same sizing intent to drag handles and numeric fields without modifying colliders or rewriting old documents.

The editor's percentage scale control changes width and height together in one history action, preserving the module count and top-left position. `environmentVisualScale` derives uniform scale from existing dimensions for platforms, directional repeats and unique art. Only two-axis environment fills persist an optional positive `tileScale` (default 1) in JSON v1, because their dimensions describe the filled area independently of cell size. Validation rejects this field on other assets/types and validates scaled cell budgets before saving or playtest. Platform drag snapping follows the scaled module size; the original 128px width restriction remains only for legacy terrain/platforms. Both render paths use the same scale, so saved levels need no alternate layout or migration.

`GameConfig` derives the exact asset dependencies from the canonical/override document and passes them to `BootScene`. Missing required images block startup with their paths. `EditorScene` queues only placed resources and redraws after loading; palette images stay outside Phaser. Historical scenes and unchanged campaign documents request no additional textures. The searchable `AssetLibrary` and `EnvironmentInspector` remain within the existing development-only editor import; no lifecycle or physics ownership changes.

### Reversible elevator commands

Elevator mode `controlled` targets progress 1 while powered and 0 otherwise. `WorldState` chooses direction each step, so signal changes or explicit commands reverse in place. Existing `once` and `pingpong` data retain pause-without-power semantics. Newly placed elevators default to `controlled`. `WorldSystem` retains swept collision/rider checks and renders both travel directions; `WorldAudio` already follows actual progress. Optional lever `action`/`targets` reuse switch commands and their priority; absent fields retain signal-only toggle behavior. Renaming, group duplication and validation cover both source types. Runtime commands are attempt-local and never enter progress saves. React inspector configuration remains discrete; it does not drive per-frame physics.

### Startup timing and stacked cargo

The installed Phaser clock normally caps the first 120 rendered frames to its 60 Hz target. At a real 30 Hz this advances only half of wall-clock time, causing apparent slow motion that disappears after warm-up. `GameConfig` uses `panicMax: 0` and `deltaHistory: 1`, retaining smoothing's large-delta protection and the existing foreground/pause lifecycle. Arcade still integrates fixed 60 Hz steps; player speeds, jump impulses and element rules are unchanged. `startupTiming.test.ts` exercises the installed TimeStep at 15/30/60/120 Hz, focus recovery and a long stall. `startup-speed-smoke.js` measures real browser movement from startup with reduced RAF frequency.

`BlockStackTransport` runs after world mechanisms on each Arcade `worldstep`. It selects one prior top contact per block, resolves stacks from bottom to top and adds only the support's actual horizontal displacement. Stationary or blocked supports therefore provide no carry; independent motion is preserved. Swept displacement respects enabled colliders, one-way gate permissions and the player. Cargo blocked by a wall may lose its moving support and fall. Existing top contact on a resting support is reconciled by at most 2 px to remove Arcade's multi-body separation jitter; ascending, detached, disabled and plate-latched bodies are excluded. Gravity and plate latches remain with the existing block/state systems. No stacking metadata, schema migration or progression write is needed. Teardown removes the listener and contact history; restart reconstructs them. Browser tests cover two/three blocks, both directions, obstacles, support loss, plate docking, non-Earth contact and full reset.

## Illustrated environments

The audited `illustratedManifest.json` registry contains only verified static layers and animation sheets. `illustratedCatalog` derives deduplicated dependencies; `illustratedAssets` loads visible resources and releases unused editor textures. `renderIllustration`, shared by editor and gameplay through `renderObject`, owns sibling render nodes to place gameplay between static world and foreground. Its owner container destroys those nodes; local sprite animations avoid global registrations surviving texture eviction. Uniform object dimensions transform source-pixel coordinates into world coordinates without resizing textures.

Schema-v1 `illustration` objects serialize registered scene ID, enabled layers and editable overlay instances. Separate `boxCollider` objects feed the existing Arcade solids, including player, heavy-block and projectile collisions. Illustration art never supplies implicit collision. The editor draws collider guides and commits each draw/drag as one history transaction. A mode switch applies immediately to the live scene rather than waiting for the boot polling interval. Existing mechanism, save and campaign rules are unchanged. See [the illustrated environment guide](illustrated-environments.md) for exact assets, limits and laboratory verification.

## Exit presentation

Schema-v1 puzzle exits render the supplied ancient doorway and masked magical seal through `renderExit`. `ForestPuzzle` detects prerequisite transitions and owns the attempt-local `ExitReveal` timeline. MainScene advances that timeline while physics and world updates are held; `RunSession.setPresentation` excludes its time without entering the application's paused state. Completion remains gated until the camera has returned. Cancellation tolerates Phaser's camera/physics plugins having already shut down. Editor initialization also ignores cancelled mounts whose loader is still finishing. See [exit-door.md](exit-door.md).
